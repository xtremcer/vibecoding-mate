# Vibecoding Mate 需求说明

## 1. 项目目标

使用 Raspberry Pi Pico、INMP441、实体按键和 LED，制作一个无需常驻上位机的 USB 复合设备。

设备通过单根 USB 线同时获得供电并传输数据，Windows 优先。

## 2. USB 功能

设备必须作为 USB 复合设备枚举，并同时提供：

1. USB Audio Class 数字麦克风
2. USB HID 自定义键盘

固件优先使用 TinyUSB 实现 USB 设备功能。

## 3. 音频输入

- 音频来源：INMP441 数字麦克风
- 总线：I²S，必要时使用 RP2040 PIO 实现
- 初始目标：单声道、16-bit、16 kHz
- 音频用途：交给 Windows 音频系统和微信输入法进行语音识别
- 不使用常驻上位机或专用驱动

## 4. PTT 按键行为

### 按下

- 发送一次 Left Win + Grave（反引号）组合键，用于触发微信输入法快捷键
- 开始本次有效音频采集和 USB 音频传输
- LED 显示 PTT 激活状态

### 松开

- 停止本次有效音频传输
- 发送 HID 全键释放报告，确保没有修饰键卡住
- LED 返回待机状态

PTT 必须采用去抖处理，并保证按下、松开事件各只触发一次。固件不得在 USB HID 回调中执行阻塞式音频读取。

## 5. 其他实体按键

设备提供 6～8 个其他实体按键。

- 每个按键只发送单键或组合键
- 不启动麦克风
- 不与麦克风执行并行传输逻辑
- 每个按键需要定义按下、松开和去抖行为
默认使用 GP3～GP10，共 8 个按键：Enter、Backspace、Ctrl+A、Ctrl+C、Ctrl+V、Ctrl+L、Esc，以及微信输入法长时语音切换。

长时语音键不是 PTT：它发送一次 `Win+Shift+F9`，再次按下再发送一次相同组合键。微信输入法需将该组合键配置为长时语音的开始/停止快捷键。功能键在 PTT 按住期间被忽略，避免与音频会话并行注入键盘事件。

## 6. LED

初始建议定义：

- 常亮或短暂亮起：设备已通电
- PTT 按下：持续亮起
- USB 未准备好或发生错误：使用闪烁模式

具体 LED 数量和引脚在硬件接线确认后固定。

## 7. Windows 验收标准

- 设备可正常枚举为麦克风和 HID 键盘
- Windows 声音设置中可以选择该麦克风
- PTT 按住时可以持续获得有效音频
- PTT 松开后不再产生本次语音输入
- Win+` 状态不会卡键
- 其他按键可被当前激活窗口接收
- 无需安装常驻上位机
- 可被微信输入法、Codex、WorkBuddy、Claude CLI 等当前激活窗口使用

## 8. 待确认参数

- Raspberry Pi Pico 具体型号：RP2040 Pico 或 Pico 2
- INMP441 的实际接线和左右声道配置
- PTT 使用的 GPIO
- 6～8 个功能键的数量、GPIO 和键位映射
- LED 数量、类型和 GPIO
- 外接状态输出：GP11、GP12、GP13 接 LED，GP14 接蜂鸣器；GP15～GP17 预留扩展
- OLED 扩展：使用 4 针 I²C OLED，GP16=SDA、GP17=SCL；GP15 保留为备用接口
- USB 音频采样率是否固定为 16 kHz，或需要兼容 48 kHz
- 松开 PTT 后采用停止 USB 音频端点，还是继续发送静音帧

## 9. 开发阶段

1. 建立并验证 Pico 固件工程
2. 单独验证 HID 键盘
3. 单独验证 INMP441 采集
4. 实现 USB Audio Class 麦克风
5. 合并 USB Audio + HID 复合设备
6. 加入 PTT 状态机、按键去抖和 LED 状态
7. 在 Windows 上进行完整验收
